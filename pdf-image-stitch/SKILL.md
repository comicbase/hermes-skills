# PDF 内嵌图裁剪拼接

PDF 的每一页往往就是一张扫描/拍照的图。本技能从页面里取出**内嵌的原始图**（不渲染页面），按比例或像素裁剪任意部分，上下（或左右）拼成一张，全程**只做一次 JPEG 编码**：裁剪零损失，体积可控。

## When to Use

- 用户给一个 PDF，说「每页其实就是一张图片」，要求取某页的上部/下部几份拼成一张。
- 用户强调「保持清晰度」「最好原图直接处理」「不要转 PNG，太大了」。
- 散在两页上的同一份东西要合成一图：证件正反面、票据上下联、合同首页+末页。

Don't use for：PDF 里是文字排版而非内嵌图（用 `pdf` 技能）、需要 OCR 取字（用 `ocr-and-documents`）。

## 核心原则（先读，决定成败）

1. **别渲染页面。** `magick identify x.pdf` / `pdftoppm` 默认 72dpi，会把 2480×3507 的原图报成 595×842。`magick` 给出的是**页面渲染尺寸，不是内嵌图尺寸** —— 照它做就降质了。
2. **抽内嵌流。** `page.get_images(full=True)` + `doc.extract_image(xref)`；DCTDecode 的 JPEG 会**原字节**返回，即零损失拿到原图。
3. **裁剪在像素域是无损的。** 按行/列切片不是缩放，不引入任何损失；损失只来自最后存盘那一次编码。
4. **合并成单张 JPEG 必须重编码一次**（JPEG 码流无法拼接）。所以策略是「裁剪零损失 + 只编码一次」，并把质量与色度采样**对齐源图**；盲目 q100/4:4:4 只会体积翻倍、肉眼无差。
5. **PNG 只当本地无损参考**（2480×3507 约 2.2MB），交付默认给 JPEG。

## Prerequisites

- `uv`。脚本随时按需拉包，无需预装：`uv run --with pymupdf --with pillow python ...`
- 可选：`brew install jpeg-turbo`（`cjpeg`/`jpegtran`）、`magick`（探参数），非必需。

## Quick Reference

```bash
# 1) 看每页内嵌图：尺寸/编码/色度采样/内容行区间 —— 定裁剪线的依据
uv run --quiet --with pymupdf python scripts/stitch_pdf_images.py probe in.pdf

# 2) 原字节抽图（需要单独交原图时）
uv run --quiet --with pymupdf python scripts/stitch_pdf_images.py extract in.pdf -o outdir

# 3) 第 1 页取上 1/3 + 第 2 页取下 2/3 → 单张 JPEG
uv run --quiet --with pymupdf --with pillow python scripts/stitch_pdf_images.py stitch in.pdf \
  -p 0:0:1/3 -p 1:1/3:1 -o out.jpg --quality 90
```

部分写法：`页号:起点:终点`，值可以是 `1/3`、`0.25`（比例，按 `Fraction` 精确换算）或 `1200px`、`1200`（像素行号，从 0 起，终点不含）。多个 `-p` 自上而下堆叠。常用开关：`--trim`（先裁到内容边界）、`--gap 40`（部分间插白边）、`--png`（无损容器）、`--quality`/`--sampling`、`--verify`（打印与无损参考的 PSNR）。

## Procedure

1. **probe**：确认每页内嵌图的分辨率、编码、采样，以及内容落在哪些行区间。完成标志：能说出「第 N 页的正文内容在 x%–y% 高度」。
2. **定裁剪线**：让线落在内容区间之外的空白上。用户直接给了比例（如 1/3）就照用，但要确认线没切到内容（probe 的行区间 + 第 5 步的条带抽查）。完成标志：每条裁剪线都在空白行上。
3. **stitch** 出图，不要额外缩放、不要转 PNG。完成标志：输出尺寸 = 各页图宽 × 各部分行数之和。
4. **校验**：`--verify` 报 PSNR 与最大单像素偏差。PSNR 随内容密度波动极大，别当硬指标 —— 实测白底扫描件 52.99 dB、密排文字区 38.20 dB，后者照样肉眼无差。硬信号是**最大单像素偏差**（正常 ≤ 45）和 PSNR **低于 30**、max **超过 80**，那说明参数选错了或源图已被重复压缩过。
5. **裁切线抽查**：把每条裁剪线附近 ±100 行切成横条看一眼，确认没切掉笔画/边框。这步比看缩略图可靠：缩略图上 1% 的差别看不见，实际可能正切在文字上。
6. **交付**：`MEDIA:` 绝对路径发给用户，并报体积与尺寸。

## Pitfalls

1. **拿渲染尺寸当原图尺寸** —— 本技能最高频的错误，见核心原则 1。
2. **一页不止一张内嵌图**（水印/logo/背景各一张）—— probe 会全部列出，脚本默认用像素数最多的那张；要指定时用 `--index`。
3. **图的变换**：只有 `get_image_bbox()` 与页面尺寸吻合，才能确信「这张图铺满整页」；否则要先渲染页面再处理。
4. **比例换算的 ±1 行误差**：`0.3333*3507` 不等于 `3507/3`。脚本用 `Fraction` 精确算，手写代码要照做。
5. **连续两次有损编码会累积可见的块状伪影**（q60 源图再 q60 存一次就糊了）。只编一次，且略高于源图质量：probe 出的源图质量估值 +5～+30 即可。
6. **扫描边框/噪点会骗过内容边界框**：扫描件四周的边框线/装订阴影是满行满列的黑，任何占比阈值都推不掉，不处理的话内容框会等于整页、`--trim` 白做。脚本两道措施：内容阈值用**绝对值**（0-255 占比刻度上的 1.5 —— 噪点在 0.5 以下、真内容在 1 以上，分界很干净）+ 四周排除 1.5% 边缘（`content_box(edge=)` 可调）。**别用「最大值的百分比」当阈值**：密集区域会把稀疏但真实的内容（如证件左侧那几行文字）一并滤掉，切出来的框会缺一条。
7. **别给公开仓库塞样张**：仓库 `.gitignore` 常含 `*.jpg`/`*.jpeg`，技能目录只放 `.md` 和 `.py`。

## Privacy（硬规则）

处理的是证件/合同/票据等私人 PDF 时：

- **不得**把原图、裁切结果、任何页面文本上传到公开仓库或第三方服务；只在本地磁盘处理。
- 技能文档、脚本、示例里**只写方法**，不带样本数据、不带真实姓名/号码/地址。
- 回复用户时按需描述结构（如「第一页是证件人像面、第二页是国徽面」），**不复述号码、地址等原文内容**。
- 要发布本技能/相关脚本到公开仓库，先跑一遍发布前闸门检查（敏感信息、密钥、个人标识、绝对路径）。

## Verification

- 输出宽 == 各页图宽（不一致时脚本补白并告警）。
- 输出高 == Σ 各部分保留行数（+ `--gap`）。
- `--verify` 的两个数：最大单像素偏差 ≤ 45、PSNR ≥ 30（实测：白底扫描件 52.99 dB/31，密排文字区 38.20 dB/42，均肉眼无差）。
- 每条裁剪线附近 ±100 行条带肉眼确认无内容被切断。
